# Law Links Detector

Сервис для выделения юридических ссылок из русского текста. Проект выполнен в рамках группового задания №1 по NLP.

## Как мы понимаем задачу

На вход сервис получает произвольный текст. В тексте необходимо найти ссылки на конкретные нормы права и представить каждую найденную норму как `LawLink`:

```json
{
  "law_id": 1,
  "article": "12",
  "point_article": "1",
  "subpoint_article": "б"
}
```

`law_id` должен соответствовать документу из предоставленного `law_aliases.json`. Статья, пункт/часть и подпункт извлекаются из текста ссылки.

Если одна текстовая конструкция содержит несколько структурных элементов, сейчас мы трактуем её как несколько отдельных ссылок. Например, `пп. 1, 2, 3 п. 2 ст. 3 НК РФ` превращается в три `LawLink`.

Если конкретный документ нельзя однозначно определить и найдено несколько возможных `law_id`, такая ссылка не попадает в обычный результат и сохраняется отдельно как ambiguous.

## Общая идея решения

Мы не пытаемся распознать юридическую ссылку одним большим регулярным выражением. Обработка разделена на несколько небольших этапов:

```text
text
  ↓
поиск локальных признаков
  ↓
сегментация потенциальных юридических ссылок
  ↓
определение конкретного документа
  ↓
извлечение структуры нормы
  ↓
LawLink[]
```

Сначала независимые стратегии находят статьи, пункты, подпункты, названия и семейства документов (`code`, `federal_law`, `presidential_decree` и т. д.). Затем близкие признаки объединяются в одну потенциальную ссылку, после чего resolver пытается определить конкретный `law_id`. На последнем этапе списки структурных элементов раскрываются в отдельные `LawLink`.

Подробное описание алгоритма и архитектуры находится в [docs/algorithm.md](docs/algorithm.md) и [docs/architecture_short.md](docs/architecture_short.md).

## API

FastAPI-сервис предоставляет:

- `POST /detect` — однозначно распознанные юридические ссылки;
- `POST /detect-ambiguous` — ссылки, для которых найдено несколько возможных документов;
- `GET /health` — проверка доступности сервиса.

Swagger доступен по адресу `http://localhost:8978/docs`.

## Структура проекта

Папки разделены по назначению, чтобы отдельно держать исходные материалы, данные для проверки, реализацию и вспомогательные инструменты:

- `dataset/` — данные для проверки поведения детектора на текстах с известным ожидаемым результатом;
- `docs/` — отдельная техническая документация по алгоритму и архитектуре, чтобы не перегружать README;
- `hw_examples/` — исходные материалы и примеры из задания преподавателя, сохранённые как точка отсчёта;
- `law_aliases/` — подготовленное представление справочника юридических документов, которое использует resolver;
- `scripts/` — небольшие утилиты для ручного запуска и проверки сервиса;
- `smoke_tests/` — сценарии для быстрой ручной проверки отдельных этапов pipeline и целых примеров;
- `src/` — основной код приложения;
- `tests/` — автоматические тесты, запускаемые через pytest.

## Docker и публикация image

Приложение собирается в Docker image и запускается как FastAPI-сервис на порту `8978`.

GitHub Actions автоматически запускает тесты для изменений проекта. Публикация Docker image в GitHub Container Registry выполняется только при создании и отправке version tag вида `v*` (например, `v0.1.0`). Перед публикацией workflow собирает image и проверяет, что контейнер успешно запускается и отвечает на `/health`.

Для каждого релиза публикуются version tag и `latest`.
