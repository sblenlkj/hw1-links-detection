# Performance benchmark

Локальный benchmark полного пути `LinksFinalizer.extract()`.

## Зачем

По условиям проверки преподавателя решение должно обработать 4 скрытых benchmark-набора по 500 текстов каждый, то есть 2000 текстов суммарно, не более чем за 5 минут. Указанный baseline проходит все четыре набора примерно за 14 секунд.

Этот benchmark не воспроизводит скрытые данные и поэтому не предсказывает их точное время выполнения. Его задача — быстро проверить порядок производительности текущей реализации и обнаружить очевидные performance-регрессии.

## Данные

В качестве одного относительно насыщенного текста используется:

`dataset/markdown/00_readme_example.md`

Один и тот же текст последовательно обрабатывается 500 раз одним экземпляром `LinksFinalizer`. Перед измерением выполняется один warm-up вызов.

## Запуск

```bash
pytest tests/performance/test_benchmark.py -s
```

`-s` нужен, чтобы pytest показал benchmark-статистику.

Вывод содержит:

- суммарное время обработки 500 документов;
- среднее время на один документ;
- количество документов в секунду;
- линейную оценку времени для 2000 документов.

## Интерпретация

Лимит преподавателя в 300 секунд на 2000 текстов соответствует в среднем 150 ms на текст.

Baseline 14 секунд на 2000 текстов соответствует примерно 7 ms на текст.

Сравнивать эти числа напрямую нужно осторожно: скрытые benchmark-наборы могут отличаться длиной текстов, количеством ссылок и сложностью разрешения документов.

В тесте намеренно нет timing assertion. Время зависит от CPU, нагрузки системы и окружения, поэтому benchmark запускается вручную и используется как диагностический инструмент, а не как обязательный correctness-test CI.
