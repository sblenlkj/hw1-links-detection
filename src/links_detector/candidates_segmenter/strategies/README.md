# Candidate strategies

Стратегии в этом слое не должны возвращать просто «окно текста, где, возможно, что-то есть».

Их задача — найти **сильный сигнал** юридической ссылки и, если это можно сделать дешёво и надёжно, сразу извлечь полезную метаинформацию для следующих этапов.

Общая идея:

```text
text
  -> independent strategies
  -> enriched candidate signals
  -> merge / matching
  -> final legal reference
```

## 1. Discourse strategy

Ищет фразы, которые часто стоят непосредственно перед юридической ссылкой:

- `согласно`;
- `в соответствии с`;
- `на основании`;
- `в силу`;
- `руководствуясь`;
- другие похожие конструкции.

Это прежде всего **маркер начала**.

После найденного discourse marker стратегия должна проверить, что справа действительно начинается что-то похожее на структуру юридической ссылки: числа, буквы, `п.`, `ч.`, `ст.`, `статья` и т.п.

Если проверка проходит, стратегия возвращает полезный `start_index` для потенциальной ссылки.

Не нужно просто брать фиксированное окно вида «ещё 300 символов вправо».

## 2. Structure strategy

Ищет структуру самой юридической ссылки.

Главный anchor — статья:

- `ст.`;
- `статья`;
- `статьи`;
- `статье`;
- другие допустимые формы.

Статья является наиболее важным структурным элементом, поэтому желательно начинать поиск именно с неё.

После обнаружения article marker стратегия должна попытаться извлечь ближайшую структуру:

```text
подпункт? -> пункт | часть? -> статья
```

Например:

```text
пп. 1, 2, 3 п. 2 ст. 14
```

Идеально, если эта стратегия со временем будет возвращать уже частично распарсенную структуру, а не просто позицию слова `статья`.

Fallback для конструкций без статьи можно добавить позже отдельно.

## 3. Quote / title strategy

Ищет текст в кавычках:

```text
"О персональных данных"
«О государственной регистрации недвижимости»
```

Кавычки сами по себе не означают юридический документ.

Поэтому после нахождения quoted span стратегия должна по возможности сразу проверить название по нашей базе документов.

Если название найдено, стратегия может вернуть уже сильный сигнал:

- `law_id`;
- границу конца названия документа;
- при необходимости family документа.

Например:

```text
Федерального закона "О персональных данных"
                    ^^^^^^^^^^^^^^^^^^^^^^^
```

может сразу дать:

```text
law_id = ...
end_index = ...
```

Если название не найдено в базе, такой quote можно либо отбросить, либо оставить как слабый candidate — это решим позже.

## 4. Merge idea

Стратегии должны дополнять друг друга.

Типичный хороший случай:

```text
Согласно п. 2 ст. 14 Федерального закона "О персональных данных"
^         ^        ^                    ^
start     structure                      resolved law/title
```

После этого merge-слой должен сопоставить близкие сигналы:

```text
START -> STRUCTURE -> LAW
```

и собрать из них одну потенциальную юридическую ссылку.

## Current principle

Не пытаться заранее извлекать большой произвольный context window.

Каждая стратегия должна:
1. найти свой сильный anchor;
2. проверить локальную структуру вокруг него;
3. извлечь максимум дешёвой и надёжной метаинформации;
4. передать компактный результат следующему слою.
